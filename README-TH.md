# Bewpakorn Queue 1.3.6

ส่วนขยาย Chrome จัดคิวออเดอร์แมพจากเก่าไปใหม่ เปิดหน้าแก้ไขออเดอร์ ล็อกอินบัญชีลูกค้าผ่านเบราว์เซอร์แยก และนำเข้าบัญชีที่ยืนยันแล้วไป Bewpakorn RAM คุณเปิดเกม ส่งของ และเปลี่ยนสถานะบนเว็บเอง

## ใช้งาน

1. เปิด Bewpakorn RAM และปลดล็อก แล้วเข้าสู่ระบบเว็บร้านใน Chrome
2. ในหน้าตั้งค่าเลือกแมพและสินค้าที่จะทำ เช่น เลือกเฉพาะ Cameraman Tower Defense แล้วบันทึก
3. กดไอคอน Bewpakorn Queue เพื่อเริ่ม ระบบเลือกออเดอร์ PROCESSING ที่เก่าสุดจากทุกหน้า และใช้แท็บแก้ไขออเดอร์เบื้องหลังแท็บเดิม
4. ช่อง **บัญชีลูกค้า** เลือกได้ทั้งบัญชีจากออเดอร์นี้และบัญชีที่มีใน RAM ช่อง **บัญชีของคุณ** เลือกจาก RAM การเลือกมีผลเฉพาะงานนี้
5. เมื่อล็อกอินจากออเดอร์สำเร็จ ระบบตรวจตัวตนและยืนยันว่าบันทึกเข้า RAM แล้ว บัญชีที่เลือกจาก RAM จะตรวจเซสชันเดิมโดยไม่เขียนทับหรือนำเข้าซ้ำ
6. ถ้าพบรหัสผิด OTP CAPTCHA หรือปัญหาอื่น ระบบแจ้งสาเหตุแล้วรอคุณจัดการ เมื่อจะไปคิวถัดไปให้กด **สำเร็จ**
7. กด **ย้อนกลับออเดอร์** เพื่อกลับไปออเดอร์ล่าสุดที่เคยกดสำเร็จ งานที่ค้างอยู่จะกลับไปเข้าเงื่อนไขคิวเก่าสุดตามปกติ การย้อนกลับไม่เปลี่ยนสถานะในเว็บ

รุ่นนี้ไม่มีการเปิดหรือปิด Roblox อัตโนมัติ ไม่มีการตรวจห้อง Private หรือบังคับสองไคลเอนต์ คุณเลือกบัญชีและเข้าเกมใน RAM เอง

## 1.3.6 — ตรวจค่าหลังพิมพ์

รุ่นก่อนพิมพ์แล้วไม่ตรวจผล ถ้าหน้าเว็บวาดช่องรหัสผ่านใหม่กลางคัน ค่าที่ได้จะว่างหรือขาด และระบบตีว่า “ฟอร์มเปลี่ยน” แล้วหยุด รุ่นนี้ล้างช่องก่อนพิมพ์ทุกครั้ง อ่านค่ากลับมาตรวจ แล้วพิมพ์ซ้ำอีกครั้งจากช่องว่างถ้ายังไม่ตรง ค่าที่คนแก้เองจะไม่ถูกล้าง ถ้ายังไม่สำเร็จ ระบบเก็บลำดับ stage ไว้ใน `loginView` ให้ตรวจได้

## 1.3.5 — กรอกเหมือนคนจริง

เดิมระบบเขียนค่าลงช่องด้วยสคริปต์แล้วกดปุ่มด้วย `element.click()` ทันที อีเวนต์ทั้งหมดจึงเป็นของปลอม ซึ่งเป็นรูปแบบที่ Roblox ตอบกลับด้วยการ์ดตรวจคน รุ่นนี้เปลี่ยนไป **พิมพ์ด้วยคีย์บอร์ดจริง** ผ่าน DevTools protocol (isTrusted ทุกตัว, 28–72 มิลลิวินาทีต่อตัวอักษร) และ **คลิกด้วยเมาส์จริง** ที่ตำแหน่งปุ่มบนจอ ถ้าพิมพ์ไม่ได้จะกลับไปใช้วิธีเดิมเป็นทางลับ

มีตัวทดสอบ `tests/native/InputProbe.cs` ที่พิสูจน์ว่า DOM ได้อีเวนต์ trusted ทั้งหมด ค่าตรง และคลิกส่งฟอร์ม 1 ครั้ง (โหมด `live` ยิงหน้า `/login` จริงด้วยบัญชีปลอม)

## 1.3.4 — หยุดรอผิดหน้าต่าง

ป็อปอัปที่ไม่เกี่ยวกับการตรวจคน (คุกกี้ โฆษณา เมนู) เคยถูกนับเป็นการยืนยันตัวตน ทำให้งานหยุดรอทั้งที่ฟอร์มยังกรอกได้ รุ่นนี้ต้องมีหลักฐานจริงก่อนหยุด: captcha หรือข้อความอย่าง verify you're human / press and hold จึงนับ และถ้าการหยุดมาจาก dialog ที่อ่านไม่ได้แต่ฟอร์มยังใช้ได้ ระบบจะกลับมาทำงานเองภายใน 15 วิ

ข้อความบนหน้าจอตอนรอจะถูกบันทึกไว้ใน `loginView` และถ้าการยืนยันไม่เสร็จภายใน 10 นาที ออเดอร์จะยังบล็อกพร้อมสาเหตุจริงแต่กดเตรียมใหม่ได้

## 1.3.3 — หน้าต่าง “Verify you're human”

หน้าต่างล็อกอินใช้โปรไฟล์เบราว์เซอร์เดียวร่วมกันทุกครั้ง (เดิมสร้างใหม่และลบทิ้งทุกออเดอร์ ทำให้ Roblox มองว่าเป็นเครื่องแปลกหน้าและขอตรวจบ่อย) คุกกี้ล็อกอินถูกล้างก่อนเปิดและก่อนปิดหน้าต่างเสมอ จึงไม่มีเซสชันค้างอยู่บนเครื่อง

ถ้า Roblox ยังขึ้นการ์ด **Verify you're human / Press and hold** ให้กดค้างในหน้าต่างล็อกอินนั้น ระบบไม่ล้างรหัสทิ้งระหว่างคุณยืนยัน และจะกรอก/กดให้ต่อทันทีที่ผ่าน (เดิมเลยเวลากรอก 60 วิระหว่างยืนยันแล้วจึงค้าง)

## หน้าล็อกอินสองแบบ (1.3.2)

Roblox แสดงหน้าล็อกอินได้ทั้งแบบเต็มหน้าและแบบกรอบ “Login to Roblox” ที่มีปุ่ม **Log In** ระบบรองรับทั้งสองแบบและกรอก **ช่องซ้าย (ชื่อผู้ใช้) ก่อน** แล้วจึงกรอกรหัสผ่านเมื่อช่องขวาเปิดให้ใช้ จากนั้นจึงกดปุ่มให้เอง กรอบล็อกอินไม่ถูกมองว่าเป็น challenge อีกต่อไป ถ้าระบบยังทำต่อไม่ได้ คุณยังกรอกและกดในหน้าต่างที่เปิดไว้เองได้ ระบบจะรับเซสชันเมื่อล็อกอินสำเร็จ

## ความหมายของสถานะ

**พร้อมใช้งานใน RAM** หมายถึงตรวจเซสชันบัญชีได้ และในกรณีบัญชีจากออเดอร์ได้ยืนยันการนำเข้าแล้ว คุณยังต้องเปิดเกมและตรวจสินค้าเอง

ออเดอร์ที่ย้อนกลับมาและเว็บเป็น COMPLETED ยังสามารถล็อกอินได้เพราะคุณสั่งย้อนกลับเอง ส่วน FAILED/CANCELLED/REFUNDED จะให้ดูข้อมูลและเลือกบัญชี RAM เอง โดยไม่อ่านรหัสเพื่อล็อกอินอัตโนมัติ

การเปลี่ยนบัญชีลูกค้าจะยกเลิกหน้าล็อกอินเดิม การเปลี่ยนบัญชีของคุณจะคงหน้าล็อกอินลูกค้า/OTP ไว้ เลือกสองช่องเป็น UserID เดียวกันไม่ได้ หาก RAM ยังไม่ยืนยันผลนำเข้า ระบบรอให้ผลเดิมชัดเจนก่อนเปลี่ยนบัญชีหรือคิว

## ติดตั้งหรืออัปเดต

รัน `scripts\install.ps1` โดย RAM ปกติอยู่ `Desktop\bew` ถ้าอยู่ที่อื่นใช้ `-RamDirectory 'โฟลเดอร์ RAM'` ไม่ต้อง Administrator

โหลดส่วนขยายจาก `%LOCALAPPDATA%\BewpakornQueue\extension` ใน `chrome://extensions` ตรวจ ID `fniggkiipecbpmobhcgkehbmjlgkldop` ถ้าเดิมโหลดจาก `D:\BewpakornQueue-1.0.0\extension` ให้ใช้ไฟล์ใหม่ในโฟลเดอร์นั้นแล้วกด **Reload** หนึ่งครั้ง

ข้อมูลคิวและประวัติเดิมเก็บไว้ ไม่มีการเริ่มออเดอร์ใหม่ตอนติดตั้งหรือเปิด Chrome หากมีงานเดิมที่ล็อกอินไม่สำเร็จ กดไอคอนเพื่อเตรียมงานเดิมอีกครั้งได้

## การเก็บข้อมูล

รหัสผ่านใช้ชั่วคราวในหน่วยความจำและหน้าล็อกอินแยก ไม่เก็บในประวัติหรือ Chrome storage บัญชีใหม่ใน RAM อยู่ Default และบัญชีเดิมคง alias/description/group เดิม ระบบจำไอดีร้านที่ป้องกันไว้แม้คุณปิดแมพนั้นในตั้งค่า

## ตรวจระบบ

`node --test tests/*.test.mjs tests/extension/*.test.mjs` ตรวจคิว การสลับบัญชี คำสั่งย้อนกลับ กดซ้ำ และการกู้คำสั่งเมื่อการเชื่อมต่อหลุด `scripts\build-native.ps1` ตรวจ build และ native fixture โดยไม่ใช้บัญชีลูกค้าจริง ชุดทดสอบหน้าจออยู่ใน `tests\extension\panel-browser.cjs` และ `options-browser.cjs`
## แก้การรอยืนยันตัวตน — 1.3.1

ยังใช้หน้าต่างล็อกอิน Queue แบบเดิม เมื่อ Roblox แสดง Verify you're human / Press and hold, CAPTCHA, OTP หรือการยืนยันทางมือถือ ระบบแจ้งสาเหตุจริงและรอคุณทำในหน้าต่างนั้นเอง ไม่กดปุ่มยืนยันแทน ไม่กรอกทับ และไม่กด Sign in ซ้ำ เมื่อผ่านแล้วจะตรวจตัวตนและนำเข้า RAM ตามเดิม

ระหว่างรอยืนยันจะไม่เปลี่ยนเป็นข้อผิดพลาดหมดเวลาทั่วไป หากปิดหน้าต่างหรือ Reload จะเลิกรอหน้าต่างที่ปิดไปแล้วและให้เตรียมออเดอร์เดิมใหม่ได้ ปุ่มสำเร็จยังใช้ไปคิวถัดไปได้ตามที่คุณต้องการ

ส่วนกรอกข้อมูลจะตรวจช่องและปุ่มที่มองเห็นจริง รอ DOM พร้อมโดยไม่ต้องรอรูปทั้งหน้าโหลด ตรวจข้อมูลก่อนกดและกู้เฉพาะช่องที่ถูกเว็บล้างก่อนส่งคำขอเท่านั้น การอ่านยืนยันเซสชันสะดุดชั่วคราวลอง GET ได้ไม่เกินสามครั้ง โดยไม่ลองนำเข้า RAM ซ้ำ
