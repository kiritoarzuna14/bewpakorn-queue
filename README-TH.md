# Bewpakorn Queue 1.0.1

ผู้ช่วยเตรียมบัญชี Roblox สองฝั่งสำหรับออเดอร์แมพ: ลูกค้า + บัญชีร้านใน Bewpakorn RAM เรียงเก่าสุดก่อน เปิดหน้าแก้ไขออเดอร์ไว้ให้ แล้วรอปุ่ม **สำเร็จ** เพื่อไปงานถัดไป

## ติดตั้งครั้งแรก

1. เปิด Bewpakorn RAM และปลดล็อกตามปกติ ให้ช่องทางนำเข้าพร้อมใช้งาน
2. รัน `scripts\install.ps1` ด้วย PowerShell ของผู้ใช้ Windows คนเดียวกับ RAM (ไม่ต้อง Administrator) ถ้า RAM อยู่ที่อื่นใช้ `-RamDirectory 'ที่อยู่โฟลเดอร์ bew'`
3. เปิด `chrome://extensions` เปิด Developer mode แล้วเลือก **Load unpacked** ที่ `%LOCALAPPDATA%\BewpakornQueue\extension` ตรวจชื่อ **Bewpakorn Queue** และ ID `fniggkiipecbpmobhcgkehbmjlgkldop`
4. เปิดรายละเอียดส่วนขยาย > Extension options เลือกบัญชีร้านหนึ่งบัญชีต่อแมพจากชื่อ/description และ Place ID ที่ตรงกัน ตรวจรายการสินค้า แล้วกดบันทึก แผนที่ตั้งต้น: Cameraman Tower Defense, Murder Mystery 2, Skibidi Tower Defense
5. ล็อกอินเว็บร้านใน Chrome ตามปกติ แล้วกดไอคอน **Bewpakorn Queue** เพื่อเริ่มงาน

เมื่ออัปเดต ติดตั้งไฟล์ใหม่แล้วกด Reload ของส่วนขยาย ตั้งค่ากับประวัติเดิมยังอยู่ เริ่มเฉพาะเมื่อกดไอคอน ไม่เริ่มงานลูกค้าตอนติดตั้งหรือเปิด Chrome เอง

รุ่น 1.0.1 มี **ทำแมพนี้** และ **เลือกเฉพาะแมพนี้** ในหน้าตั้งค่า เช่น กดเลือกเฉพาะแมพนี้ใต้ Cameraman Tower Defense แล้วบันทึก คิวถัดไปจะรับเฉพาะสินค้าที่เลือกของ Cameraman ออเดอร์ปัจจุบันยังอยู่จนคุณจัดการเสร็จ ไม่มีการย้ายข้ามงานปัจจุบันจากการตั้งค่า

แก้การตรวจหน้า Sign in รุ่นใหม่ที่ปุ่มไม่มี ID เดิม และแก้ลำดับการรอปุ่ม: ตรวจช่อง กรอกหนึ่งครั้ง แล้วรอให้ปุ่มพร้อมก่อนส่ง หากงานเดิมค้าง LOGIN_FORM_TIMEOUT ก่อนมีการส่งจริง หลัง Reload จะกดไอคอนเพื่อเตรียมออเดอร์เดิมต่อได้ ระบบเปลี่ยน generation/token เพื่อกันคำตอบเก่า โดยไม่เพิ่มออเดอร์นั้นในประวัติสำเร็จ กรณีเคยส่งล็อกอินหรือมีผลนำเข้าไม่ชัด จะไม่ใช้เส้นทางกู้แบบนี้

ตัวติดตั้งวาง native แต่ละรุ่นแยกโฟลเดอร์ จึงเตรียมอัปเดตได้ขณะรุ่นเก่ายังเปิดอยู่ การ Reload ใน Chrome จะเปิดใช้รุ่นใหม่ ถ้าโหลด unpacked จากโฟลเดอร์อื่น ต้องอัปเดตไฟล์ในโฟลเดอร์ที่ Chrome โหลดจริงด้วย

## ใช้งานประจำ

- ระบบอ่านออเดอร์แมพที่อนุญาตและมีสถานะ PROCESSING ไล่ครบทุกหน้า เลือกเก่าสุดก่อน ไม่รวมกลุ่มแมพจนข้ามคิว
- เปิดหน้าแก้ไขออเดอร์ใหม่ ระบบไม่รีเฟรชหน้าแก้ไขที่คุณกำลังทำอยู่
- หน้าล็อกอินลูกค้าแยกจาก Chrome ส่วนตัว เมื่อได้เซสชันจะตรวจ UserID และนำเข้า RAM บัญชีร้านตรวจเซสชันที่เก็บไว้แล้ว
- ถ้ารอยืนยันมือถือ, OTP, CAPTCHA, รหัสไม่ผ่าน หรืออ่านข้อมูลไม่ได้ จะแจ้งและรอคุณ คุณจัดการหน้าเว็บ/เกมเอง
- กด **สำเร็จ** เมื่อจัดการหรือผ่านงานนี้แล้ว ปุ่มเดียวนี้ไปคิวถัดไปได้แม้งานมีปัญหา ไม่ได้เปลี่ยนสถานะร้าน
- คิวหมดแล้วจบรอบ กดไอคอนอีกครั้งเมื่อจะเริ่มรอบใหม่ ปิด Side Panel ไม่เท่ากับกดสำเร็จ

## ขอบเขตที่ควรทราบ

“ล็อกอินแล้ว” หมายถึงตรวจตัวตน/เซสชันตรงบัญชี และลูกค้านำเข้า RAM ผ่านการยืนยันการบันทึกแล้ว ไม่ใช่หลักฐานว่าเกมโหลดเสร็จหรือส่งสินค้าแล้ว รุ่นนี้ไม่กดเทรด ซื้อ ส่งของ เปลี่ยนสถานะ หรือบันทึกหน้าแก้ไขออเดอร์

RAM v30 ไม่มี API ตั้งกลุ่ม จึงผูกบัญชีกับออเดอร์ในประวัติ Queue บัญชีลูกค้าใหม่จะอยู่ Default ใน RAM บัญชีเดิมคง alias/description/group เดิม ไม่เขียนไฟล์บัญชีที่ RAM เปิดอยู่เอง ปุ่มสำเร็จไม่ลบเซสชันที่นำเข้า RAM; คุณลบบัญชีผ่าน RAM ได้เอง ไม่เก็บรหัสผ่านลูกค้าเพิ่ม

ถ้าโฮสต์ปิดระหว่างงาน ระบบคืนงานเดิมและแจ้งให้ตรวจสอบก่อน ไม่ลองรหัสซ้ำเอง ถ้าการนำเข้ากำลังส่งไป RAM ระบบรอให้คำขอเดิมจบก่อนเปิดงานใหม่ ป้องกันการผูกเซสชันข้ามงาน ประวัติ handled เก็บใน `%LOCALAPPDATA%\BewpakornQueue\data` ห้ามลบประวัติเพื่อแก้ปัญหา เพราะออเดอร์ PROCESSING ที่เคยผ่านแล้วอาจกลับมา

หากขึ้น **RAM ยังไม่ยืนยันผลนำเข้า** หลังคุณกดสำเร็จ ระบบจำคำสั่งไว้และรอผลเดิม ถ้า RAM ไม่ตอบกลับต่อ ให้ปิด RAM ตามปกติเพื่อยุติคำขอที่อาจค้าง แล้วเปิดใหม่ ระบบจะตรวจผลและรับคำสั่งเดิมให้เสร็จ กดไอคอนเพื่อเริ่มคิวต่อได้ ไม่ต้องกดสำเร็จซ้ำ ห้ามเปิด RAM หลายชุดพร้อมกัน เพราะระบบจะหยุดเพื่อป้องกันนำเข้าผิดโปรแกรม

## ตรวจระบบ / ถอนติดตั้ง

`scripts\verify-installed.cjs` ตรวจเฉพาะ handshake, ความพร้อม WebView2 และจำนวนบัญชีที่อ่าน metadata ได้ ไม่เริ่มออเดอร์หรือนำเข้าเซสชัน

ถอนส่วนขยายจาก Chrome แล้วรัน `scripts\uninstall.ps1` จะเอาทะเบียนและไฟล์โปรแกรมออก เก็บประวัติคิวและบัญชี RAM ไว้

มีซอร์สและชุดทดสอบมาด้วย: Node.js ใช้ `node --test tests/*.test.mjs tests/extension/*.test.mjs`; native ใช้ `scripts\build-native.ps1` และ `node tests/native/protocol.cjs` การทดสอบจำลองไม่ใช้รหัสลูกค้าจริง
