# Bewpakorn Queue

ระบบช่วยจัดคิวออเดอร์บริการแมพ Roblox สำหรับร้าน Bewpakorn เชื่อม Chrome Extension กับโปรแกรม Bewpakorn RAM บน Windows เพื่อลดงานเปิดออเดอร์ ล็อกอิน และนำเข้าบัญชีซ้ำ ๆ

ซอร์สปัจจุบันเป็นเวอร์ชัน **1.5.2** ตาม `extension/manifest.json` และ `package.json` เอกสาร `README-TH.md` อธิบายการทำงานรุ่น 1.3.0 ส่วนเอกสารแผนและรายงานใน `docs/` เก็บประวัติการพัฒนา จึงอาจต่างจากรุ่นปัจจุบัน

## การทำงานปัจจุบัน

1. เลือกแมพ สินค้า และบัญชีร้านในหน้าตั้งค่าของส่วนขยาย ระบบรับเฉพาะรายการที่กำหนดไว้
2. กดไอคอนส่วนขยายเพื่อเริ่มหรือทำงานเดิมต่อ ระบบอ่านออเดอร์สถานะ `PROCESSING` จากทุกหน้า และเรียงเก่าสุดก่อน
3. เปิดหน้าแก้ไขออเดอร์โดยใช้แท็บงานเดิม อ่านบัญชีจากออเดอร์ แล้วกรอกชื่อผู้ใช้ รหัสผ่าน และกดเข้าสู่ระบบบนแท็บ Chrome ของ Roblox รองรับหน้า `/login` ที่มีรหัสภาษาด้วย
4. ผู้ใช้จัดการ CAPTCHA, OTP และการยืนยันตัวตนด้วยตนเอง หากเซสชันใน Chrome เป็นคนละบัญชี ระบบแจ้งเตือนก่อนนำเข้า
5. ตรวจตัวตนของเซสชันให้ตรงกับออเดอร์ แล้วส่งเข้า Bewpakorn RAM โดยตรวจผลตอบรับและข้อมูลที่บันทึก เมื่อสำเร็จจึงพยายามเปิดเกมของลูกค้าตาม Place ID
6. การเปิดเกมอัตโนมัติใช้ลิงก์ Private Server ที่ตรงกับแมพจากข้อมูลใน RAM หากไม่มีลิงก์จะใช้ Public Server เมื่อเปิดเกมไม่สำเร็จมีปุ่มลองใหม่หรือเลือก Public Server ผู้ใช้ยังต้องตรวจว่าเข้าเกมและเซิร์ฟเวอร์สำเร็จจริง
7. เลือกบัญชีลูกค้าได้จากออเดอร์หรือบัญชีที่มีใน RAM และเลือกบัญชีร้านสำหรับงานปัจจุบันได้ กด **สำเร็จ** เพื่อบันทึกประวัติภายในแล้วไปคิวถัดไป หรือ **ย้อนกลับออเดอร์ล่าสุด** เพื่อกลับไปจัดการอีกครั้ง

ระบบไม่ได้เปลี่ยนสถานะออเดอร์บนเว็บหรือส่งสินค้าแทนผู้ใช้ และไม่ได้เปิดเกมบัญชีร้านสองหน้าต่างอัตโนมัติ ผู้ใช้จัดการบัญชีร้านและการส่งของเอง

## โครงสร้างและเทคโนโลยี

| ส่วน | เทคโนโลยีและหน้าที่ |
| --- | --- |
| `extension/` | JavaScript, HTML, CSS และ Chrome Extension Manifest V3: อ่านออเดอร์ แสดง Side Panel กรอกล็อกอิน และประสานงานคิว |
| `native/` | C# / .NET Framework และ Windows Forms: ตรวจเซสชัน ประสาน RAM เก็บประวัติ และสั่งเปิด Roblox |
| การเชื่อมต่อ | Chrome Native Messaging ระหว่างส่วนขยายกับโปรแกรมในเครื่อง |
| หน้าล็อกอินเดิม | Microsoft Edge WebView2 ยังอยู่ในซอร์สและการ build; เส้นทางหลักของรุ่นนี้ใช้ Chrome จริง |
| ข้อมูล | Chrome Storage สำหรับการตั้งค่า และไฟล์ JSON ในเครื่องสำหรับสถานะคิว |
| การทดสอบ | Node.js test runner, native self-tests และชุดทดสอบหน้าจอด้วย Playwright |

## ติดตั้งจากซอร์ส

ต้องมี Windows x64, Google Chrome, .NET Framework ที่รองรับ WebView2, Microsoft Edge WebView2 Runtime และ Bewpakorn RAM รุ่นที่รองรับการรับบัญชีจาก Queue หากต้องการเปิดเกมให้ติดตั้ง Roblox Player ด้วย โปรแกรม RAM และข้อมูลบัญชีไม่ได้รวมอยู่ใน repository นี้

เปิด PowerShell ที่โฟลเดอร์โปรเจกต์ แล้วรัน:

```powershell
.\scripts\build-native.ps1
.\scripts\install.ps1 -RamDirectory 'C:\path\to\bew'
```

โฟลเดอร์ RAM ต้องมี `Bewpakorn RAM.exe` และ `AccountData.json` ตัวติดตั้งใช้สิทธิ์ผู้ใช้ปัจจุบันและลงทะเบียน Native Messaging ใน `HKCU` สคริปต์ build ดาวน์โหลด WebView2 SDK ตามเวอร์ชันและ SHA-256 ที่กำหนดไว้

ใน `chrome://extensions` เปิด Developer mode แล้วเลือก **Load unpacked** จาก `%LOCALAPPDATA%\BewpakornQueue\extension` จากนั้นเปิด RAM เข้าสู่ระบบเว็บร้าน และตั้งค่าแมพกับบัญชีในส่วนขยาย หากอัปเดตให้ Reload ส่วนขยายหลังติดตั้ง

## พัฒนาและตรวจสอบ

ใช้ Node.js ที่รองรับ `node:test` สำหรับชุดทดสอบ JavaScript:

```powershell
npm test
```

ตรวจ build และ native self-tests:

```powershell
.\scripts\build-native.ps1
```

สร้างแพ็กเกจสำหรับติดตั้ง:

```powershell
.\scripts\package.ps1 -OutputDirectory 'C:\path\to\release-output'
```

ชุดทดสอบส่วนใหญ่ใช้ข้อมูลจำลอง การผ่าน self-tests ไม่ได้ยืนยันว่าการล็อกอินหรือเข้าเกมจริงจะสำเร็จในทุกสถานการณ์

## ข้อมูลในเครื่อง

สถานะติดตั้งและคิวอยู่ใน `%LOCALAPPDATA%\BewpakornQueue` ส่วนข้อมูลบัญชีอยู่ในโฟลเดอร์ RAM รหัสผ่านออเดอร์ใช้ชั่วคราวสำหรับล็อกอินและไม่บันทึกในประวัติคิว ห้ามนำข้อมูลบัญชี เซสชัน คุกกี้ ลิงก์ Private Server หรือไฟล์ runtime จริงมาใส่ใน repository
