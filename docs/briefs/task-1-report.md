# Task 1 native companion report

Implemented native messaging framed JSON with strict size limits and exact configured extension origin, single-host named mutex, durable atomic ledger with backup and fail-closed corruption/restart recovery, claims, completion tokens and replay, snapshots/events, read-only DPAPI RAM metadata, operator identity validation and saved-place mismatch protection. Only order metadata is persisted. The config file beside the executable is `config.json`, containing `extensionOrigin`, absolute `ramDirectory`, and absolute `dataDirectory` (environment variables expanded).

Customer preparation uses an isolated WebView2 profile, fixed HTTPS Roblox top-level host allowlist, one automatic form submission, human interaction in the same window, authenticated username/UserID validation, operator-role conflict check, the fixed v30 RAM import endpoint and legacy adapter origin, verified protocol-2 ACK, and read-only RAM persistence check for the exact expected UserID and cookie. A lock fences import against completion; restart blocks the old job. Import uses `prepareNextAccount=true`. It never writes RAM AccountData directly. New RAM accounts remain in RAM's Default group; the requested customer group cannot be created with the existing receiver. Order association is workflow metadata only.

Build pins official Microsoft.Web.WebView2 1.0.3537.50 NuGet package and verifies SHA-256 `5EA526BBD728ADDA0DA4D31219267E96460494A427E4894C4E09D9F320F4B9AA`, then compiles with Framework64 csc into native/bin. `--self-test` exercises frames, claim/completion replay, durable reload, and corrupt-ledger failure using temporary files. `node tests/native/protocol.js` exercises actual framed process communication, empty initial customer username, missing-operator block, stale completion, replay, and handled order rejection. Both passed. No live customer login, import, or RAM database mutation was performed.

Limitations: WebView selectors and challenge behavior are not validated against a live Roblox session; the implementation does not classify individual challenge types or wrong-password evidence. Third-party challenge navigation is blocked by the host-only navigation allowlist and may prevent a challenge from completing. WebView profile deletion is best effort after close and may be delayed by browser processes; it can contain an isolated session. No mocked HTTP import/race integration test was completed, so the login/import path and crash timing require further verification before production use. Adapter ACK and persisted cookie checks are implemented but not tested against a running RAM receiver. Runtime availability is detected; import support reports implemented capability rather than the live receiver's readiness.
