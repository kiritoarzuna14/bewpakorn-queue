# Task 1 native companion report

Native messaging implements bounded length-prefixed JSON, exact configured extension origin, a named mutex, atomic ledger with backup and corruption/restart recovery, claims, completion tokens and replay, snapshots/events, read-only DPAPI RAM metadata, operator identity validation and saved-place mismatch protection. Only workflow/order metadata is persisted. The config file beside the executable is `config.json`, containing `extensionOrigin`, absolute `ramDirectory`, and absolute `dataDirectory` (environment variables expanded).

Customer preparation creates an isolated WebView2 profile, restricts top-level navigation to HTTPS Roblox hosts, waits up to 30 seconds for the login form to mount and makes at most one automatic submission. DOM evidence signals phone, OTP, CAPTCHA, and explicit wrong-password states without exporting page text. The window remains available for human completion, with cookie polling and independent operator status. Authentication validates username and UserID, checks operator-role conflict, then uses the fixed RAM v30 endpoint and legacy adapter origin, protocol-2 ACK and read-only RAM persistence identity/cookie verification. The import request has a 20-second abort deadline. Completion serializes against import and persistence; a completed job cannot initiate a later import. Isolated profiles are under the configured data directory; deletion is attempted after disposal and retried on the next startup.

RAM receives `prepareNextAccount=true` and is never modified directly. The receiver has no group API. Capabilities expose `customerGrouping:false` and `groupPolicy:default-preserve-existing`. Newly added accounts remain in Default and existing metadata is preserved. The ledger records `ลูกค้าจากออเดอร์` as a workflow category, not a RAM group.

Build pins official Microsoft.Web.WebView2 1.0.3537.50 NuGet package with SHA-256 `5EA526BBD728ADDA0DA4D31219267E96460494A427E4894C4E09D9F320F4B9AA`, copies SDK license and notices, and compiles with Framework64 csc into native/bin. `--self-test` uses temporary files and fake authentication/import/persistence adapters to exercise successful identity/ACK/persistence, mismatch, role conflict, challenge recovery, negative ACK, mismatched persisted cookie, cancellation before import, completion waiting on an in-flight import, replay, and corrupt-ledger failure. `node tests/native/protocol.cjs` checks framed communication, grouping capability, empty initial username, missing operator, stale completion, replay and handled rejection. Both passed. No live customer login, import, or RAM database mutation was performed.

Limitations: actual Roblox login DOM and challenge behavior have not been validated in a live customer session; DOM indicators are conservative and not exhaustive. Third-party challenge navigation is blocked by the host-only navigation allowlist and may prevent a challenge from completing. Browser processes can delay profile deletion until the next startup. The adapter and race tests inject fake responses at the HTTP adapter boundary; they do not exercise a running RAM receiver or real network/socket behavior. The runtime and receiver must be validated with an authorized customer before relying on this workflow.
